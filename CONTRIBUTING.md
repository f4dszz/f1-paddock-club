# Contributing to F1 Paddock Club

Thanks for your interest. This guide is the human-facing companion to
`CLAUDE.md` / `AGENTS.md` (which are written for coding agents). It consolidates
the branch policy, the local gates, the commit conventions, and the
documentation-sync expectations that already exist across the repo's scripts.

## Before you start

This is a portfolio-stage multi-agent demo, not a framework. The guiding
principle is **targeted fixes, not rewrites**: keep behavior changes small and
covered by focused tests, and do not re-architect when a small change is enough.
See `CLAUDE.md` for the full set of agent working rules and code-quality rules;
they apply to human contributors too.

## One-time setup

```bash
# Backend
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env        # optional: add LLM/provider keys for live data

# Frontend
cd ../frontend
npm ci
cd ..

# Enable the tracked git hooks (pre-push gate)
./scripts/install-hooks.sh
```

The project runs without any external keys — the first plan renders honest
estimate/mock cards. Keys are only needed for live data and chat refinement.

## Branch policy

- `main` is the deploy branch. Both Vercel and Railway auto-deploy on push to
  `main`, so it must stay green.
- Do your work on a feature branch and open a pull request. CI
  (`.github/workflows/ci.yml`) runs on every push and PR.

## Local gates (run before you push)

```bash
# Full bundled verification: doc sync, backend compile + unit tests,
# URL-normalizer skill tests, frontend npm ci + build + audit
./scripts/check-local.sh

# Browser smoke: starts backend + frontend, runs Playwright, cleans up
./scripts/e2e-local.sh

# Deterministic full E2E lane (stub-backed refine + saved-trips)
E2E_INCLUDE_REFINE=1 E2E_INCLUDE_SAVED=1 LLM_STUB_MODE=1 ./scripts/e2e-local.sh
```

The pre-push hook (`./scripts/install-hooks.sh` enables `.githooks/pre-push`)
gates every push on `check-agent-doc-sync.sh` + `check-local.sh`. Run
`./scripts/check-agent-doc-sync.sh` on its own to confirm `AGENTS.md` and
`CLAUDE.md` are byte-for-byte identical.

A targeted, faster loop while iterating:

```bash
# Backend unit tests only
backend/.venv/bin/python -m unittest discover -s backend/tests -v

# Frontend build only
cd frontend && npm run build
```

## Commit conventions

- **No AI attribution in commit messages.** Do not add `Co-Authored-By:` trailers
  or any "generated by" lines. This rule is intentional and is also enforced for
  agents in `CLAUDE.md`.
- Write imperative, descriptive subject lines (e.g. "Fix budget incomplete on
  one-way-only flights"), and explain the *why* in the body when it is not
  obvious.
- Keep each commit focused. Prefer small, reviewable slices over one large
  rewrite.

## Documentation sync expectations

A few documents are kept in lockstep and the gates will fail if they drift:

- **`AGENTS.md` and `CLAUDE.md` must stay byte-for-byte identical.** Edit both
  when you change either; `scripts/check-agent-doc-sync.sh` enforces this.
- **`README.md` and `README.zh-CN.md`** should stay in sync. There is no
  automated check for the two READMEs yet, so update the Chinese version (or its
  "trails EN" banner) whenever you change user-facing English docs.
- **`CHANGELOG.md`** tracks user-visible behavior changes under `[Unreleased]`.
  Add an entry for anything a user or operator would notice.
- **`docs/current.md`** is the canonical near-term status snapshot. Keep its test
  count, shipped-vs-pending status, and "remaining gaps" accurate.

## Honesty and trust rules

These are product invariants, not style preferences:

- Booking/search links must never imply a confirmed purchase. Search and
  homepage links need honest copy.
- Expose honest source/degradation metadata; never silently swallow provider
  failures.
- Any selected unpriced item must produce an **incomplete** quote, not a green
  within-budget total.
- Budget recomputation for quote previews must be side-effect-free.
- Keep the mock/estimate path as a permanent graceful-degradation fallback.

## Reporting security issues

Do **not** open a public issue for a vulnerability. See `SECURITY.md` for the
private disclosure process.
